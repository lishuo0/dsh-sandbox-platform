# 客户端接口

平台面向浏览器的全部接口都在统一前缀下，平台是唯一的授权边界。
这份文档给前端/桌面端与排障使用：端点表、传输格式、SSE 帧、错误码、不支持清单。

对应实现：`src/client/surface.ts`（入口与授权）、`src/client/mux/router.ts`（unary Remote）、
`src/client/mux/sse.ts`（流）、`src/client/mux/queue.ts`（输入队列）、
`src/client/transport.ts`（前端传输适配）。

## 1. 总则

- **统一前缀**：`/dsh-api/platform/v1`（下称 `P`）。前缀之外的任何 HTTP 请求一律 404；
  平台不注册任何 Upgrade 监听，WebSocket 握手拿不到 101。
- **登录**：`POST /login`（表单 `username` / `password`）下发 HttpOnly cookie
  `platform_session`；反代声明 `x-forwarded-proto: https` 时加 `Secure`。`POST /logout` 清 cookie。
  除 `POST /login` 外，所有 `P/*` 端点未登录返回 `401 unauthorized`。
- **租户**：所有端点先按会话/工作区归属判定。跨成员的 id 一律按不存在处理
  （错误码 `session/not-found`），且**不会**转发给脑。跨成员不返回 403 或存在性信息。
- **停用成员**：token 未过期但成员已停用时同样 401。
- **脑凭据**：`x-app-id` / `x-app-key` / `x-dsh-user-id` / `x-dsh-workspace-id` 只在平台到脑的
  内部请求上出现；浏览器带来的 cookie 永远不转发给脑。

## 2. 传输格式

前端由 `src/client/transport.ts` 注入的 `__DSH_TRANSPORT__` 适配官方客户端：

- `connection.rpc.call('/api', '<endpoint>', {args})` → `POST P/remote/<endpoint>`
- `connection.rpc.open('/api', '<endpoint>', payload, signal)` → `GET P/sse/<endpoint>?payload=<base64url JSON>`
- 文件字节上传 → `POST P/upload?<query>`
- 页面不再建立全局 WebSocket。

### 2.1 unary Remote 信封

请求：

```json
{ "type": "client-request", "rpcId": "<唯一号>", "method": "<endpoint>", "payload": { "args": { } } }
```

- `method` 必须与路径里的 `<endpoint>` 一致，否则 `endpoint-mismatch`。
- `session/*`、`workspace/*`、`session/prompt` 等把参数包在 `args.request` 里；
  `$events/result`、`userQuestions/answer`、反馈类把参数平铺在 `args` 里。

回复（HTTP 永远是 200，成败看 `result.ok`）：

```json
{ "type": "server-response", "rpcId": "<请求里的 rpcId>",
  "result": { "ok": true, "value": {} } }
{ "type": "server-response", "rpcId": "<请求里的 rpcId>",
  "result": { "ok": false, "error": { "code": "<错误码>", "message": "", "details": {} } } }
```

### 2.2 SSE 帧

`GET P/sse/<endpoint>?payload=<base64url(JSON)>`，`payload` 是内层 `{ "args": { } }`。
响应 `text/event-stream`，每条 `data: <JSON>` 是一帧；`event: error` 表示该流失败并结束；
空闲时服务端下发 `: ping` 注释与 `retry:` 不承载数据。

## 3. 平台自有（非 Remote）面

| 方法与路径 | 说明 |
| --- | --- |
| `POST P/upload?sessionId=&name=&mediaType=` | 会话附件/粘贴图片直传平台存储；回 `receiptId`、`file`/`image`（图片带 `width`/`height`） |
| `POST P/workspaceFiles/upload?workspaceId=&path=` | 工作区文件上传 |
| `POST P/context/<endpoint>` | 上下文洞察（genui 等），只认 POST |
| `GET P/sessions/{id}/stream` | 会话实时面（平台中转脑的 `/brain/v1/sessions/{id}/stream`），授权在开流之前完成 |
| `POST P/sessions/{id}/answers` | 交互答复上行；body `{requestId, outcome, sessionId?}`，`sessionId` 与路径不符返回 409 |
| `GET /`、`/plugins/*`、genui assets | 外壳页与静态资源 |

## 5. SSE 流端点（`GET P/sse/<endpoint>`）

| endpoint | 帧 |
| --- | --- |
| `session/follow` | `snapshot` → `event` / `assistant-stream`，以及转发事件 |
| `session/control` | `baseline` → `projection` |
| `session/observeEvent` | `ready` → `event` |
| `session/observeProjections` | `ready` → `projection` |
| `session/observeState` | `ready` → `state` |
| `job/list` | 脑的后台任务清单帧 `rows` |
| `job/follow` | 单个任务的 `opened` / `output` / `status` |
| `userQuestions/attachWait` | `remainingMs`，待答请求结算后关流 |
| `$events` | `ready {clientId,host}`、`emit`、`waterfall`、`cancel` |

### `session/follow` 快照

```json
{ "type": "snapshot",
  "header": { "version": 4, "id": "<sessionId>", "createdAt": 0, "cwd": "/desk", "isSeeded": false },
  "cursor": 3,
  "records": [],
  "hasMore": false,
  "projections": { "asOfSeq": 3, "values": { "inbox": { "next-turn": [], "next-step": [] } } },
  "assistantStream": { "revision": 0 } }
```

之后：

- 脑的日志事件 → `{type:"event", event:{type,seq,time,data}}`（seq 单调递增，重复帧被丢弃）；
- 脑的内容流 → `{type:"assistant-stream", frame:{...}}`；`start` 变体补 `startedAfterSeq`
  （快照/最近事件的 seq），后续增量原样下发；
- `waterfall` 帧在 `$events` 已连接时广播为 `{type:"waterfall", event, eventId, agentId, request}`。

### `session/control`

`baseline` 带缓存里每条会话的 `{asOfSeq, values}`；之后写操作触发的投影变化与
队列变化（1s 轮询）都以 `{type:"projection", sessionId, seq, changes:[{key,val}]}` 下发。

## 6. 平台输入队列与 `inbox`

- `session/prompt` **不同步转脑**：消息写 `dsh_session_queue`，回 `{accepted:true}`。
- 平台为每个会话维持一个泵：订阅脑的会话 SSE，等 `status.running === false`
  后按 `created_at` 顺序发 `POST /brain/v1/sessions/{id}/messages`
  `{text, requestId, mode:"queue"}`，成功即出队。
- 脑的 inbox 正常为空；客户端的「待发送」卡片来自平台注入的投影：
  `inbox["next-turn"][i] = { id, source: { kind:"user", rpcId:<原 requestId> }, content }`。
- `session/updateQueue`：`edit` 改正文；`remove` 删除；`steer` 在当前回合运行时
  立即以 `mode:"steer"` 下发，不在运行时返回 `session/steer-unavailable`。
- 队列落库，进程重启后按会话恢复。

## 7. 错误码

| 码 | 含义 |
| --- | --- |
| `session/not-found` | 会话不存在或不属于调用者（跨租户统一用这个） |
| `workspace/not-found` | 工作区不存在或不属于调用者 |
| `session/id-invalid` | 缺会话 id 或格式不对 |
| `session/model-config-required` | 没配置模型或选了名单外的模型 |
| `session/inactive` | 会话已归档，不能发消息 |
| `session/queue-item-not-found` | 队列项不存在 |
| `session/steer-unavailable` | 当前没有运行中的回合可并入 |
| `workspace/move-invalid` | 会话不在该工作区 |
| `gateway/bad-request` | 参数形状不对 |
| `gateway/not-found` | 端点/命名空间在浏览器面上不存在 |
| `gateway/unauthorized` | 未登录或成员已停用 |
| `gateway/internal` | 脑不可达或内部错误 |
| `endpoint-mismatch` | 请求 `method` 与路径不一致 |
| `not-found` / `session-not-found` | 平台内部码，对客户端映射成 `session/not-found` |

`P/upload`、`P/workspaceFiles/upload` 等非 Remote 面用 `{ok, value|error}` 形状，
`error.code` 取值同上。

## 8. 浏览器面上不存在（一律 404，不转发）

- 宿主机路径/桌面端能力：`session/openWorkspacePath`、`session/canOpenWorkspacePath`、
  `session/workspacePathApplications`、`directoryPicker/*`、`officeKit/*`。
- 进程级设置写入：`settings/mutate|update|replace|openSettingsDocument`
  （`settings/describe` 只读；权限预设只按会话走 `commands/execute` 的 `/permission`）。
- 部署级管理面：`account/*`、`credentials/*`、`mcpManager/*`、`pluginManager/*`、
  `pluginMarket/*`、`pluginRegistryProbe/*`、`pluginInventory/*`、`dynamicCordisRunner/*`、
  `terminal/*`、`subagents/*`、`workspaceFiles/changes`。
- 全局推送：`workspace/follow`、`remoteAccess/follow`、`account/watch`、
  `mcpManager/watch`、`toolResults/watch`、`productAnalytics/watchPolicy`。
- 会话列表的实时增删、跨会话运行角标等依赖全局连接的能力不提供，改由 REST 拉取。
