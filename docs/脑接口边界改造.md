# 脑接口边界改造方案

> 硬约束 1：**脑只对外暴露有文档的 API 接口；未文档化的接口一律不许存在。**
> 硬约束 2：**实时面不用 WSS。** 下行一律是会话级 SSE（一条流一个会话），上行一律是 REST；任何全局（跨会话）推送一律禁止，需要全局推送的能力不提供，改为 REST 拉取。脑不注册任何 Upgrade 路由。
> 状态：实施中 · 2026-11-17（实时面方案 2026-11-18 由 WSS 改为 SSE）

## 1. 背景

脑当前同时挂了两套接口：

| 接口面 | 来源 | 状态 |
|---|---|---|
| `/brain/v1/*`（HTTP + SSE） | `packages/dsh-platform-api` | 已写进 `dsh-sandbox-brain/docs/接口.md` |
| `/api/*` + `WSS /api/remote.mux` | profile 插入的 `@deepseek-ai/dsh-client-connection`、`@deepseek-ai/dsh-api-remotes`、`typert-gateway` | **未文档化，且不认租户** |

平台现在把浏览器的 WSS 原样透传给脑，再用 `dsh-sandbox-platform/src/client/surface.ts` 里的 `guardClient` / `guardServer` 逐帧扫字段名（`sessionId`、`workspaceId`、`agentId`…）来兜底隔离。这违反三条约束：

1. 脑暴露了文档里没有的接口；
2. 那条 WSS 是**全局**的：一条连接承载所有会话，隔离只能靠"猜"字段名——未知子代理 ID、缺省 `sessionId` 的 `job/follow` 都能绕过；
3. 平台没有真正终结协议，只是透传。

改造后的边界（已定）：

- **WSS 在所有层都不存在。** 实时下行是会话级 SSE（原生 `EventSource` 语义，不需要 Upgrade），上行是普通 POST。浏览器到平台、平台到脑，都只有一个原则：**一条流 = 一个会话**。
- **平台对外两张面**：会话级 SSE（只承载该会话的实时帧）+ 全局 REST（不绑定会话的请求/响应，见 4.1.1）。
- **脑侧两个面**：会话级 SSE（该会话的事件/状态/审批/提问）+ 原子 HTTP（给定 `sessionId` 的动作与事实，含答复上行）。
- **平台能自己实现的自己实现；不能实现的（只存在于 Agent 运行时的实时事实）经会话级 SSE 转发给脑。**
- **输入队列在平台**（见 4.3）。

```
浏览器 ──SSE /dsh-api/platform/v1/sessions/{id}/stream（每会话一条）──▶ 平台
       ──REST /dsh-api/platform/v1/*（全局数据、会话动作、答复上行）──▶ 平台
                              │
                              ├── SSE  /brain/v1/sessions/{id}/stream ───────▶ 脑（事件/状态/交互请求）
                              ├── HTTP /brain/v1/sessions/{id}/answers ─────▶ 脑（交互答复上行）
                              ├── HTTP /brain/v1/* ──────────────────────────▶ 脑（原子动作）
                              └── 平台数据库 / 对象存储（租户、归属、历史、设置、附件、队列）
```

脑不注册任何 Upgrade 路由（启动审计强制为 0）。浏览器的 SSE 永远只到平台，浏览器也永远看不到脑凭据。

## 2. 边界判定规则

提出任何新能力时按顺序判：

1. 数据是否只存在于脑或沙箱（实时 Agent 状态、会话日志、后台任务、沙箱文件、附件）？
   - 是 → 在 `/brain/v1` 新增**文档化**的接口（HTTP，或 3.2 的会话级 SSE）。
   - 否 → 平台自己实现，不进脑。
2. 客户端调用了、但平台和脑都没有对应能力 → 回 `gateway/not-found`，并记一条日志；不许"顺手"透传。
3. 脑上新增任何路由（HTTP 或 Upgrade）都必须先写进 `docs/接口.md`，否则测试失败。
4. 原子性：脑接口只回答"这个 `sessionId` 的某个动作/事实"，不提供按用户过滤的列表、不存业务状态
   （队列、标题、归档、置顶、归属），也不做业务判断。任何带业务属性的能力一律平台实现。
5. **实时流必须绑定会话**：SSE 路径携带且只携带一个 `sessionId`；帧里不得出现指向其它会话的标识；
   脑和平台都按流钉死会话，不信任帧内字段。上行答复的路径与请求体也必须指向同一会话。
6. **禁止全局推送**：任何需要跨会话/全局推送的能力一律不提供，改为全局 REST 按需拉取（见 4.1.1）。
   也不引入 WSS：实时面只有会话级 SSE。
7. **服务端强制鉴权**：任何人拿到的数据都必须先在服务端按 `userId` 校验归属。客户端传来的
   `userId` / `sessionId` / `workspaceId` / `jobId` / `attachmentId` 只是"候选标识"，不构成授权。
   查不到或不属于当前用户一律回 not-found（不暴露存在性），且**不得调用脑**。

## 3. 脑侧改造

  - `session-controller`、`job-controller`、`workspace-controller`、`settings-controller`、`ui-settings`、`workspace-files`、`workspace-files-session`。
  - 保留标准：`/brain/v1` 的实现是否直接依赖它提供的内部服务。依赖就留插件、但不许它再注册 `/api` 路由；先把注册表打出来再定。
  - `approval`、`user-questions` **保留**：它们是被 Agent 工具调用的原子能力，不是 `/api` Remote 面；由 3.2 的会话级 SSE 对外暴露。

- 脑监听地址只绑 `127.0.0.1`（或部署内网地址）。

**全局 Upgrade（`/api/remote.mux`）必须消失**；脑不注册任何 Upgrade 路由，实时下行走 3.2 的会话级 SSE。

### 3.2 新增会话级 SSE（下行）+ 答复 POST（上行）

两条路径，都是普通 HTTP，没有 Upgrade：

| 方向 | 方法 + 路径 | 说明 |
|---|---|---|
| 下行 | `GET /brain/v1/sessions/{id}/stream` | `text/event-stream`；每个 `data:` 都是一个下行帧的 JSON |
| 上行 | `POST /brain/v1/sessions/{id}/answers` | 请求体 `{ requestId, outcome }`；答复回到该会话的 answerer |

会话标识在**路径**里（`{id}` 经 `encodeURIComponent`），不再放 query。SSE 响应头固定为
`content-type: text/event-stream; charset=utf-8`、`cache-control: no-store`、
`connection: keep-alive`、`x-accel-buffering: no`（关掉反代缓冲）。

#### 3.2.1 协议

事件名固定为 `frame`，`data` 是 JSON 帧。最小帧集：

| 方向 | `type` | 字段 | 说明 |
|---|---|---|---|
| S→C | `ready` | `sessionId`、`seq` | 首帧；`seq` 是当前日志偏移，客户端据此回填历史 |
| S→C | `event` | `seq`、`event` | 会话日志事件 |
| S→C | `status` | `running` | Agent 运行状态 |
| S→C | `stream` | `frame` | Assistant 流式帧 |
| S→C | `waterfall` | `requestId`、`kind`、`request` | `kind`: `approval` \| `questions` \| `plan` |
| S→C | `cancel` | `requestId` | 请求已被撤回/结算 |
| C→S | `answers` POST 体 | `requestId`、`outcome` | `{kind:'result',value}` 或 `{kind:'rejected',error}` |

没有 `ping`/`pong`：SSE 的存活由服务端每 15s 写一行 `: keepalive` 注释维持，
浏览器按 `EventSource` 的重连语义重连；平台把连接关闭等价于旧协议里的断开。

`answer` 的 `value` 与 Agent 的 answerer 一一对应：审批是 `'approved'` / `'denied'`，
提问和计划评审是 `answers`（形状沿用 `@deepseek-ai/dsh-user-questions` 的请求体）。

#### 3.2.2 会话钉死

- `GET …/{id}/stream` 与 `POST …/{id}/answers` 路径里的会话是这条流/这次答复**唯一**的会话。
  答复体里若出现 `sessionId` 且与路径不符 → 409 `session/mismatch`；
  答复的 `requestId` 必须属于本会话的待答表，否则 409（不关闭流）。
- 脑不认识租户：只校验应用凭据（`auth.ts` 的 `x-app-id` / `x-app-key`）与用户头；
  归属校验由平台在打开流之前完成，脑只保证"这条流/这次答复碰不到别的会话"。
- 会话不存在（冷启动也解析不到持久日志）→ `GET …/stream` 直接返回 HTTP 404，
  在写出任何 SSE 字节之前拒绝。

#### 3.2.3 重放与背压

- **连上先重放**：先写 `ready`，再按顺序下发当前所有未答复的 waterfall，然后进入实时帧。
  断线期间请求留在 Agent 的 answerer 里，重连必须补投，否则平台会 fail closed。
- **事件不重放**：`event` / `status` / `stream` 是尽力而为的实时信号；客户端重连后从
  `GET /projections`、`GET /events` 回填。不要在脑里做事件缓冲。
- 待答表只在内存里：脑进程重启即丢，此时 Agent 回合也随之中止（fail closed）。
- 背压：`res.write` 返回 `false` 时先等 `drain` 再继续读上游；下游 `close` 立即取消上游读取，
  不无限吃进内存。

### 3.3 新增启动期路由审计

在 `@brain/dsh-platform-api` 启动时枚举 webserver 已注册的所有路由和 Upgrade 路由，断言：

- HTTP 只允许 `/brain/v1/*` 和健康检查；
- **Upgrade 路由数量必须恰好为 0**（`auditUpgradeRoutes(webServer)` 返回空数组；
  任何注册都让 `apply()` 抛错）。

不满足直接启动失败。这条审计是"未文档化接口不许存在"的机器保障，不靠人记。

### 3.5 需要新增的脑 HTTP 接口

只加"数据只有脑有 / 动作只能在脑里完成"的原子接口，全部写进 `docs/接口.md`：

| 方法 | 路径 | 原因 |
|---|---|---|
| POST | `/brain/v1/sessions/{id}/fork` | 分支要复制会话日志，日志在脑 |
| POST | `/brain/v1/sessions/{id}/messages`（扩展） | 现在只收 `text`；增加可选 `mode: 'queue' \| 'steer'`，`steer` 立即并入当前回合 |

**审批/提问/计划评审不再新增其它接口**：下行由 3.2 的会话级 SSE 承载，上行由
`POST …/answers` 承载——这就是唯一的交互通道，同一条数据不提供第二条路径。

**为什么 `steer` 必须真实现**：上游 `session/prompt` 的 `mode: 'queue' | 'steer'` 已经存在
（`dsh-api-session-controller/src/types.ts:328`），实现分别是 `agent.followup` 和
`agent.steer`（`dsh-agent-loop/src/agent.ts:184-192`）；本工程 `gateway.prompt` 现在只有
`agent.followup`（`gateway.ts:636-639`）。`steer` = 插到当前回合的下一个 step 边界，
`queue` = 排到下一回合；不是同一个字段的两种写法。

| 原候选 | 归属 |
|---|---|
| `session/state`、`session/wait` | 平台：自己队列 + 脑会话 SSE 的 `status`/`event` + waterfall 缓存合成 `pendingInput` |
| `session/updateQueue` | 平台：队列在平台（见 4.3） |
| `workspace-files/search` | 平台：递归调现有 `list` 做本地匹配，不跑 `rg` |
| `workspace-files/changes` | 不支持，`gateway/not-found` |
| `fileReferences/list` | 平台：复用递归 `list`，只回路径候选 |
| `fileUploads/upload`、`session/attachment` | 平台：共享对象存储读写，见 3.5.2 |
| 会话列表 / 搜索 / 改名 / 工作区列表 / 目录变更推送 | 平台：全局 REST（见 4.1.1），脑不提供 |

每个新增接口都要有：请求/响应示例、错误码、`docs/接口.md` 条目、单元测试 + e2e。

### 3.5.1 E2B 只有文件系统原语

E2B 沙箱保证的是 list / read / stat / write / remove 这类文件系统操作，**不保证能执行 `rg`，也不保证有文件 watch**。所以：

- 不设计任何依赖 shell 搜索或 inotify 的脑接口，也不新增"递归列目录"接口。
- 搜索 / `@` 引用 = 平台用现有 `workspace-files/list` 有界递归（深度、条目数、总字节、超时），在平台内存里做子串匹配；结果标记 `truncated` / `incomplete`，不假装是 ripgrep。
- 文件变更（`workspaceFiles/changes`）= 不支持，回 `gateway/not-found`；不轮询、不做全树 watch。

### 3.5.2 附件与上传归平台（共享对象存储）

参考实现 `/Users/lishuo/Documents/dsh/dsh-managed-agents` 没有脑附件接口，因为平台和沙箱共用同一份 OSS：

- **上传**：平台把字节写到 workspace 卷前缀（本部署是 `desks/{workspaceId}/uploads/{sessionId}/{name}`，必须和脑 profile 的 `ossMounts.bucketPath` 一致），返回 `sandboxPath`（`/desk/uploads/...`）；Agent 在沙箱里直接读。做法同 `internal/platform/service/upload.go`。
- **读取**：平台直接读 OSS，先校验会话和工作区归属：
  - `ws:<base64url(绝对路径)>`：workspace 卷里的图片，按该工作区前缀读，路径必须落在 guest root 内；
  - `sha256:<digest>`：脑 `attachment-oss` 写入的规范化对象，先读 `attachments/v1/objects/<前两位>/<digest>`，再回退 `attachments/v1/file-objects/<digest>`，并校验 sha256。
- **发消息**：脑的 `/brain/v1/sessions/{id}/messages` 只接受文本，平台把附件转成沙箱路径/引用文本再发，不把字节塞进脑接口。
- 平台配置里的 `aliyun.oss` 已经指向同一份存储；本地模式继续落到 `storage.dir`。

因此 `fileUploads/upload`、`session/attachment` 全部平台实现，脑上不新增路由。

## 4. 平台侧改造

### 4.1 对外只有两张面

**统一前缀：`/dsh-api/platform/v1`**（现有 `src/kernel/http.ts:8` 的 `API_PREFIX`）。
平台提供的所有接口——REST 和会话级 SSE——都必须挂在这个前缀下，不存在无前缀路由。
前缀之外的 HTTP 请求和 Upgrade 一律 404，不再有 `proxyWeb`/`proxyUpgrade` 的兜底。
全文用 `P = /dsh-api/platform/v1` 简写平台路径；`/brain/v1/*` 始终是脑侧路径。

#### 4.1.1 全局 REST 是什么

**不绑定会话连接的普通 HTTP 接口**：页面需要时请求，平台按登录态和归属校验。
"全局"指的是没有会话连接这个概念（不是所有用户共用），每次请求仍只返回当前用户有权看到的数据。

| 类别 | 端点（示意，均为 `P` 下） |
|---|---|
| 会话 | `GET /sessions`、`GET /search/sessions`、`PATCH /sessions/{id}`（改名）、`POST /sessions` |
| 会话动作 | `POST /sessions/{id}/messages`、`/cancel`、`/force-cancel`、`/model`、`/fork`、`/feedback` |
| 会话快照 | `GET /sessions/{id}/projections`、`/history`、`/events?cursor=`、`/state` |
| 工作区 | `GET/POST/PATCH/DELETE /workspaces...`、`/initializeDefault` |
| 任务 | `GET /sessions/{id}/jobs`、`POST /sessions/{id}/jobs/{jobId}/kill` |
| 文件 | `GET /sessions/{id}/workspace-files*`、`GET /workspaces/{id}/files`、`POST /attachments`、`GET /files` |
| 目录/设置 | `GET /models`、`GET /permission-presets`、`GET /presets`、`GET /settings/model`、`GET /sessions/{id}/commands` |
| 其他 | `GET /schedules`、`GET /skills`、`GET /mcp-servers`、`GET /me`、`/admin/*` |

现有模块已经实现了其中大部分（`src/modules/*/routes.ts`），改造时统一走 `API_PREFIX`，
内置页面客户端（`console-client.js`、`files-upload-client.js`、`model-settings-client.js`、
`workspace-create-client.js`、`user-badge.ts`）同步改到同一前缀。

全局数据**没有推送**：进入页面/切换会话时拉取；列表变更在本端操作后本地更新。
这是硬约束 2 的直接代价，见 7 的功能缺口清单。

#### 4.1.2 会话级 SSE + 答复 POST

- 下行：`GET P/sessions/{id}/stream`，即 `/dsh-api/platform/v1/sessions/{id}/stream`。
  一条流一个会话；帧与 3.2.1 同形，平台额外下发 `queue` 帧（平台队列投影，见 4.3）。
- 上行：`POST P/sessions/{id}/answers`，请求体 `{ requestId, outcome }`，平台核对归属后
  转成脑的 `POST /brain/v1/sessions/{id}/answers`。
- 顺序固定为「认路径 → 认人 → 认成员状态 → 认会话归属 → 才连脑」；任何一步失败都在
  响应头之前回 HTTP 状态码（401/404），**绝不建立到脑的连接**。
- `surface.handle` 在 `/dsh-api/` 前缀内先认这两个路径；它们在 Route 表之外，因为需要
  原始流式写出与更早的授权顺序。`surface.upgrade` 只保留旧 `/api` 代理的过渡路径，不再有会话流。
- `prompt`/`cancel`/`fork` 等动作一律走 REST，不占流。

### 4.2 平台 mux 模块

新增 `dsh-sandbox-platform/src/client/mux/`：

| 文件 | 职责 |
|---|---|
| `protocol.ts` | 会话流/答复的路径解析（`sessionStreamId` / `answersSessionId`）、答复体校验（`parseAnswer`），会话不符 → `session/mismatch` |
| `stream.ts` | `handleStream`：认路径 → 授权 → 把脑的 SSE 原样转发；`handleAnswer`：认路径 → 授权 → 校验答复体 → 转给脑的 answers |
| `handlers/events.ts` | 脑 `event`/`status`/`stream` → 下行帧；断线后按 `seq` 回填 |
| `handlers/interactions.ts` | 脑 `waterfall`/`cancel` → 下行帧；`answer` 经 `handleAnswer` 回脑；缓存 `pendingInput` |
| `handlers/jobs.ts` | 任务列表（REST）与输出（脑 SSE → 下行 `stream` 帧） |
| `handlers/files.ts` | 当前会话所属工作区的文件流 |
| `handlers/queue.ts` | 平台输入队列：prompt / updateQueue / inbox 投影 / 回合结束后派发 |

### 4.3 输入队列归平台

队列不是脑的运行状态，而是平台对每个会话的待发送消息表：

- `P/sessions/{id}/messages`（`session/prompt`）到达时只入平台队列，立即回 `accepted: true`，不转发脑。
- 平台在会话上游 SSE 上等 `status=idle` / 回合结束帧，收到后从队列取一条，用原 `requestId` 调脑
  `POST /brain/v1/sessions/{id}/messages`，`mode: 'queue'`。
- `session/updateQueue`：`edit` / `remove` 只改平台队列；`steer` 立刻把这条以 `mode:'steer'`
  转发给脑并出队（见 3.5）。
- 同一会话任意时刻最多一条在脑里执行，脑的 inbox 正常应为空——平台是唯一排队者。
  客户端读的 `inbox` 由平台 `queue` 帧注入，形状与 DSH 一致（`{ 'next-turn': [...] }`）；
  `itemId` 由平台生成，必须与 `queue` 帧里的 id 完全一致（否则编辑会 `queue-item-not-found`）。
- `session/state` 的 `queue` 来自平台队列表，`pendingInput` 来自 `handlers/interactions.ts`
  缓存的待答请求；两者都不读脑的 inbox。
- 队列落新表 `dsh_session_queue`（`session_id`、`item_id`、`request_id`、`content`、`created_at`），
  平台重启按会话恢复；不存进程内存。
- 上游 SSE 的存活条件：有浏览器订阅者，**或** 该会话有排队消息/运行中回合。否则宽限期后关闭，
  避免为静默会话常驻连接。

这样既不会出现"平台发一条、脑再排一条"的双层队列，也不会把队列这种业务状态塞进脑。

### 4.7 鉴权与租户（硬要求）

**原则：平台是唯一的授权边界。** 脑不认识租户，任何"把脑的数据交给用户"的路径都必须先在平台
按 `userId` 校验；客户端输入只当候选标识，永远不构成授权。

1. **入口认证**：所有 REST 路由都必须显式声明 `auth: 'member' | 'admin'`（`kernel/http.ts` 的
   `Route.auth` 是必填字段，只有 `/health` 和登录接口是 `public`）；会话 SSE 同样先做
   登录 + 成员状态校验，失败直接 401/404，不建立到脑的连接。
2. **归属校验先于脑调用**：`/sessions/{id}/*` 一律先 `ownSession(db, userId, id)`，
   `/workspaces/{id}/*` 一律先 `ownedWorkspace(...)`；查不到 → 404，**并且不调用脑**。
   禁止"先转发再过滤"。
3. **不信任请求体里的主体**：`userId` 只来自 `ctx.actor`；路径里的 `{id}` 才是目标；
   请求体/查询串里的 `sessionId`、`workspaceId`、`jobId`、`attachmentId` 必须
   逐个对照当前用户的表，否则丢弃或 404。
4. **派生标识只由服务端生成**：上传对象的 key、队列 `itemId`、签名 URL 的 scope 全部由平台按
   已校验的 `workspaceId` / `sessionId` 生成，绝不拼接客户端输入。
5. **任务与附件**：`jobId` 必须经由其所属会话的归属校验（脑的 `JOB_FOREIGN_SESSION` 只作兜底）；
   `sha256:` 附件必须命中 `dsh_attachments` 且属于当前用户；`ws:` 路径必须落在当前用户
   工作区前缀内。
6. **每条流只认自己的会话**：平台为每次 `GET …/stream` 重新校验归属后才连脑，
   不复用不校验的上游；待答缓存的 key 必须是 `(userId, sessionId)`。
7. **帧级兜底**：会话 SSE 只服务路径上的那个会话；上行 `POST …/answers` 的请求体若带
   `sessionId` 必须与路径一致（否则 409），`requestId` 必须属于该会话的待答表（脑侧同样执行，见 3.2.2）。
8. **失败一律 not-found**：跨成员访问不返回 403/存在性信息，统一 404。
9. **测试是闸门**：每个 handler 都要有跨成员用例，断言"返回 not-found 且脑未被调用"；
   会话 SSE 要有"B 连 A 的会话被拒且不建上游连接"的 e2e。

调脑统一走 `BrainClient`，由它在服务端注入 `x-app-id` / `x-app-key` / `x-dsh-user-id`；
浏览器永远看不到这些头，也不再收到任何 `dsh-auth-*` cookie。

## 7. 风险与功能缺口

- **前端适配层是最大工作量**：全局连接是官方前端的传输假设，换掉它比换后端协议更费工。
  探针阶段必须先跑通"列表 + 单会话流式"，否则后面全是空转。
- **功能缺口（必须逐条签字）**：会话列表实时增删、跨会话运行角标、跨会话错误提示、
  工作区实时增量、`remoteAccess`、目录/命令/权限/设置/日程的变更推送、多会话并行流。
  这些在全局推送下才有，新方案一律不提供，改为 REST 拉取。
- **交互通道**：`approval/request`、`user-questions/request` 是 waterfall（下行请求 + 上行答复）。
  会话 SSE 与 `POST …/answers` 必须与平台同期上线，且重连要先重放待答请求；否则审批、
  `ask_user_question`、`exit_plan_mode` 评审都会 fail closed。参考项目选择 `approval: never`
  放弃这些能力；本方案选择保留，所以必须补通道。
- **队列语义**：平台是唯一排队者。平台只在脑回合结束之后派发，避免"平台排一条、脑再排一条"；
  `steer` 是唯一的立即下发路径。
- **会话 SSE 是新增面**：必须走文档 + 启动审计 + 契约测试三道闸；Upgrade 路由必须是 0。
- **事件语义**：`event`/`status`/`stream` 尽力而为、不重放；数据一致性靠持久日志 + 快照回填。
- **回滚**：不做双路径；探针失败就停在第 1 步，旧代理保持原样。
